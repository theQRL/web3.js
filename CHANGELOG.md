# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- A digest-pinned standalone go-qrl execution testnet launcher with Clef, hash archive state, HTTP/WS/IPC endpoints, and a shared two-CPU limit (`scripts/local_testnet/README.md`).
- QRNS: `getText(name, key)`, `getName(address)` (reverse resolution, forward-verified) and `setAddress(name, address, txConfig)`.
- `web3-errors`: `NodeChainIdMismatchError` (code 441), thrown when a supplied chain id does not match the connected node's.

### Changed

- **Breaking, VM64 / Hyperion 0.2.0 alignment** (the type-level changes of this cycle, listed here in one place):
  - Typed data: `Eip712TypedData` / `Eip712TypeDetails` are `QRLTypedData` / `QRLTypedDataTypeDetails`, `getEncodedEip712Data` is `getEncodedQRLTypedData`, the validator format `eip712TypedData` is `qrlTypedData`, and the required domain type is `QRLTypedDataDomain` instead of `EIP712Domain`. Typed-data hashes change accordingly.
  - `Topic` is `HexString64Bytes` (a 64-byte QRVM log topic) and `logSchema.topics` is formatted as `bytes64`; `encodeEventSignature` returns the 64-byte topic (see Fixed). A decoded `EventLog.signature`, and `decodeLog` for hashed indexed parameters, return the 32-byte keccak hash.
  - `FeeHistory.baseFeePerGas` is an array (one value per block of the window plus the next block), as `qrl_feeHistory` returns it.
  - `TransactionReceipt.root` (the pre-Byzantium state root) was removed from the type and the receipt schema.
  - `ValueTypes` and `toHex(value, true)` report `uint512` / `int512` for numbers (the QRVM word is 64 bytes); ABI address decoding returns checksummed `Q` addresses.
  - QRNS: `getPubkey` returns `{ publicKey, descriptor }` (an ML-DSA-87 key) instead of `{ x, y }`, and the `PubkeyChanged` event carries the same fields; `normalize` and `namehash` are exported from the package root again (`normalizeWithSource` is gone).
  - `web3-qrl-accounts` `Common` gas parameters for the `zond` hardfork: the Ethereum EC precompile entries (`ecAdd`, `ecMul`, `ecPairing`, `ecPairingWord`) were replaced by go-qrl's `depositroot` and `mldsa87Verify` precompiles, EIP-3860 initcode gas counts 64-byte words, and `initialBaseFee` is 100 gwei (`100000000000`), matching go-qrl's genesis fee math.
- `@theqrl/qrl-contracts` (the Hyperion contract library the test fixtures are compiled against) is a devDependency pinned to GitHub commit `d3c84eedac4e051f6e99892397c5e42f0f0a2266` instead of npm `0.1.0`: the published release (2026-04-03) predates the VM64 / Hyperion 0.2.0 contract sources. The archive is pinned by SHA-512 integrity in the lockfile and checked by `pnpm run doctor`; the cost is that installs need `codeload.github.com` and Dependabot cannot track it. Exit plan: publish a tagged `@theqrl/qrl-contracts` release built from that commit (or later) and point `package.json` back at the npm version (`docs/supply-chain-security.md`).
- **Breaking:** QRNS no longer defaults to an unverified fixture address. `registryAddresses` has no built-in deployment until issue 103 records a verified registry. Set the constructor address or `registryAddress` explicitly; unconfigured queries fail before a contract call, and `checkNetwork()` accepts an explicit registry or requires a verified network deployment.
- Fixed-size ABI byte inputs (`bytesN`) must contain exactly N bytes; callers must pad deliberately instead of relying on implicit padding. Seed strings require a lowercase `0x` prefix.
- Updated the fixture compiler to `@theqrl/hypc` 0.2.0 and regenerated contract ABIs and bytecode with optimization enabled (200 runs), keeping PublicResolver within go-qrl's deployed code size limit.
- Limited `compile:contracts` to generating and formatting contract fixtures.
- Configured local testnet client and helper images using published tags, including a compatible AMD64 genesis generator.

Unlike Node's emitter, emitting `error` without a listener returns `false` instead of throwing, so an unobserved internal error can no longer terminate a consumer through an uncaught exception. ### Removed

- The `@theqrl/web3-qrl-iban` package and the `Iban` exports of `@theqrl/web3` (`web3.qrl.Iban`, `web3.qrl.iban`, `Web3.modules.Iban`): IBAN/ICAP encoding is an Ethereum convention with no QRL counterpart. The last published version, `@theqrl/web3-qrl-iban@1.0.3`, was deprecated on npm on 2026-10-23; use checksummed QRL addresses instead.
- `qrl_protocolVersion` (`getProtocolVersion`) and `qrl_getCompilers` / `qrl_compileHyperion` (`getCompilers`, `compileHyperion`, `CompileResultAPI`) from `web3-rpc-methods`, `web3-qrl` and `web3-types`: gqrl does not implement them.
- `TransactionReceipt.root`, QRNS `normalizeWithSource`, and the dead `SendTransactionOptions.ignoreFillingGasLimit` option (see Fixed).

### Fixed

- Subscription ids returned by `qrl_subscribe` must be `0x` hex strings; any other reply rejects the subscription with a `SubscriptionError` instead of being stored and later crashing the process on a provider change, and the provider-change cleanup can no longer produce an unhandled rejection (P4-M-1).
- The subscription manager counts `qrl_subscribe` requests in flight before detaching its provider listener and re-attaches it after registering, re-subscribes live subscriptions after a socket reconnect (also on the auto-reconnect path, which re-opens the socket without a `disconnect` event; the old server-side id is released best-effort), rejects a subscription whose provider was replaced while subscribing, ignores a late `qrl_unsubscribe` acknowledgement for a re-subscribed id, and `resubscribe()` tolerates a node that no longer knows the id (P4-M-4, P4-L-1, P4-L-2, P4-L-3).
- `ParamType` and `Fragment` instances are branded with a symbol instead of a public `_isParamType`/`_isFragment` flag, and array lengths and decoded element counts must be non-negative safe integers, so a forged ABI entry can no longer bypass the decoder's byte and element budgets (P4-M-2).
- Receipt polling awaits each `qrl_getTransactionReceipt` in full and skips ticks while one is in flight instead of racing every call against the polling interval and discarding slow replies (P4-M-3).
- `format()` keeps an empty array under a `oneOf` of array schemas (`block.transactions` of an empty block), keeps `null` members the node sent (`to`, `blockNumber`, `blockHash`, `transactionIndex`, `contractAddress`, inside arrays too) and never resolves a node-supplied key against `Object.prototype` (P4-M-6).
- Timer options above 2^31 - 1 ms (`transactionPollingTimeout`, `requestTimeout`, `connectionTimeout`, batch timeouts, `blockHeaderTimeout` in seconds) are rejected instead of firing after 1 ms (P4-L-5).
- `useRpcCallSpecification` is wired to the request manager (the block-timeout flag was passed by mistake) and follows later changes of `enableExperimentalFeatures` (P4-L-4). `setConfig()` applies `transactionPollingInterval` first so an explicit receipt or confirmation interval in the same object wins regardless of key order (P4-L-6), and the configured `maxListenersWarningThreshold` applies from construction.
- Batch replies a legacy provider delivers through its error path resolve `execute()` with the array and report errors per entry on every provider kind (P4-L-7). A reply whose id does not match the request is an `InvalidResponseError` on every provider kind and is no longer re-classified as a revert by its message; a JSON-RPC revert wrapped in an `HttpStatusError` decodes from the node's own error object (P4-L-8).
- Nested ABI decode errors (a non-canonical word or invalid UTF-8 inside an array or tuple) throw an `AbiError` eagerly instead of becoming throwing getters on the result (P4-L-32); the ABI string decoder and `hexToUtf8` keep a leading byte-order mark (P4-L-33); type-string array encoders no longer split a string into characters (P4-L-34).
- `toPlanck`/`fromPlanck` reject `Object.prototype` member names as units (P4-L-35); packed encoding keeps NUL characters in strings and rejects malformed type names and array values for scalar types (P4-L-36, P4-L-42); `toHex` throws `InvalidAddressError` for an address-shaped string with a wrong checksum instead of hashing it as text, and treats `-abc` as text (P4-L-37).
- `Web3BaseProvider.asEIP1193Provider()` calls the wrapped `request` with the provider as `this` (P4-L-38); validator error messages render bigint and circular values without throwing (P4-L-39); `transformJsonDataToAbiFormat` recurses once per array dimension (P4-L-40); `isTopicInBloom` accepts unprefixed topics (P4-L-41); `isHexString8Bytes`/`isHexString32Bytes` reject a sign and enforce the exact length.
- Addresses must carry a capital `Q`, as go-qrl requires: a lowercase `q` prefix is rejected by the validator, the ABI address coder and the `defaultAccount` option (P4-L-44).
- An ABI that lists an identical function or event fragment twice registers it once (first occurrence wins), so calls by name are no longer reported as ambiguous (P4-M-8).
- Live contract event subscriptions drop logs of another address or event signature (reported on `error` only when a listener is attached) and emit logs the node marks `removed` on `changed` instead of `data` (P4-L-25). For overloaded events the name key binds the first overload, the subscription backfill replays the bound overload, and `getPastEvents` accepts the signature and signature-hash keys (P4-L-26).
- `deploy({input})` / `deploy({data})` no longer combine with the contract's `options.data` / `options.input`, so `send()`, `estimateGas()` and `encodeABI()` use the same bytecode (P4-L-27); `options.address` is honoured by the `Contract` constructor (a positional address wins) and `jsonInterface` is no longer an init-option key (P4-L-28); `getPastEvents` and the subscription backfill work with `FMT_BYTES.UINT8ARRAY` (P4-L-29); a `qrl_call` reply that is not a `0x` hex string rejects with `InvalidResponseError` instead of resolving `null` (P4-L-30); a nullish client-side `filter` value in `getPastEvents` is a wildcard.
- QRNS `getName()` validates the address and returns the reverse name only when it forward-resolves to that address (`''` otherwise), and `getText(address)` uses the verified name only (P4-L-31).
- The WebSocket and IPC providers honour `maxResponseBytes` (the WebSocket `maxPayload` defaults to it); an oversized reply fails only the request(s) it answers with a `ResponseTooLargeError` instead of every in-flight request, and the IPC stream stays in step while an oversized message is discarded (P4-M-5).
- Socket providers: the connection timer of a failed attempt is cleared when a reconnect is scheduled and stands down during the back-off (P4-L-16); a request is settled before its `message` event is emitted (P4-L-20); `connect()` rejects requests already written to the socket it replaces with `PendingRequestsOnReconnectingError` (P4-L-21); the connect error names the transport error instead of echoing a message that may quote the full URL, and the WebSocket provider refuses an unparseable URL at construction with a redacted `InvalidClientError` (P4-L-15).
- WebSocket provider: `disconnect(code, reason)` validates the close code (1000 or 3000-4999) and the reason (at most 123 UTF-8 bytes) before any teardown and a replaced CLOSING socket is terminated (P4-L-17); a replaced socket's listeners are always detached and its close event is ignored, so a request issued while the previous socket is CLOSING is served on the new one (P4-L-18); `disconnect()` while connecting no longer emits a spurious `error`.
- IPC provider: `disconnect()` emits `disconnect` once.
- HTTP provider: a failing body cancellation no longer masks `ResponseTooLargeError` or skips the transport abort (P4-L-19); a `TypeError` from `fetch` is a connection failure only in undici's `fetch failed`/`cause` shape, while a refused request (invalid header, credentialed URL) is a `ProviderError` that echoes neither (P4-L-23); documented that URL credentials only work with node-fetch.
- `EventEmitter.emit` removes the fired `once` registration itself, so a function registered with both `once()` and `on()` keeps its `on()` registration, as with Node's emitter (P4-L-22).
- Node-supplied messages in `ResponseError`, `InvalidResponseError` and `HttpStatusError` are truncated to 256 characters (new `truncateEchoedText`), the full text staying on `innerError` (P4-L-24).
- Release pipeline: `publish-tarballs.js` skips an already-published version only when the registry's `dist.integrity` equals the local tarball's SHA-512 and fails on a mismatch or a missing integrity (P4-M-9); the `prepare` job records the digests of the release candidate as job outputs and every consuming job verifies its download against them before use, the SLSA subjects are derived from those digests, and the smoke projects install with `npm ci` from a lockfile `prepare` resolved (P4-M-10); npm trusted publishing is confined to a verify-and-publish job, SBOMs are generated without an OIDC token and attestations and release uploads run outside the `npm-publish` environment (P4-M-11); a `workflow_dispatch` path rebuilds and publishes tagged-but-unpublished versions (`republish-plan.js`, `restore-tag-manifests.js`), a pre-flight fails a push release when a tagged version is missing from npm, and the release-candidate artifact is kept for 30 days (P4-M-12); SBOM attestations name the tarballs and checksum files as subjects (P4-L-48).
- Supply chain: the Trivy gate scans devDependencies locally and in CI with doctor parity, and the `undici` (6.28.1 / 7.29.1), `handlebars` (4.7.10) and `markdown-it` (14.3.3) overrides were bumped (P4-M-7); `minimumReleaseAgeExclude` entries are pinned to exact versions and doctor rejects name-only entries (P4-L-47); doctor validates `.trivyignore` revisit dates (calendar, at most two years ahead, a single marker) and reads `allowBuilds` at any indentation.
- Repository hygiene: symlinks named like excluded directories are checked, symlink targets must be under the documented allowed paths, tracked generated output is rejected under `tools/*` and `.coverage/` as well, a `.secrets.json` or `.env*` file fails only when tracked or not ignored, and `clean` keeps `.secrets.json` (P4-L-45, P4-L-50); the package inspection rejects secrets, keys, `.env*`, lockfiles and `node_modules` at any depth and `.env*` is ignored (P4-L-46); the lint budget fails when a budgeted package is no longer linted (P4-L-49); the black-box runner uses absolute paths, `set -euo pipefail`, the WebSocket port 8546 and no Verdaccio registry (P4-L-51).
- Packaging: `lib/**/*.tsbuildinfo` is excluded from every tarball, the unused webpack `stream` fallback was dropped, `husky:uninstall` runs `git config --unset core.hooksPath`, CODEOWNERS routes the release configuration to the devops team, and `ContractInitOptions` declares the `address` option.
- `sendTransaction`/`sendSignedTransaction` require the `qrl_sendRawTransaction` reply to be a 32-byte hash equal to the locally computed `keccak256` of the raw transaction (a `qrl_sendTransaction` reply must be a 32-byte hash) and emit and poll the receipt with the local hash, so a node cannot hand back the receipt of a different transaction (P4-L-9).
- The send PromiEvent is rejected before the `error` event is emitted, a throwing `error` listener or a failing custom-error decode is logged instead of leaving the send pending, and an exception thrown by a `sent`, `transactionHash` or `receipt` listener after the broadcast is delivered to the `error` listener (or logged) instead of rejecting a transaction the node already holds (P4-L-10).
- `getBlock`, `getBlockTransactionCount` and `getTransactionFromBlock` send only a 32-byte value (66-character hex string or 32-byte `Uint8Array`) to the `*ByHash` methods; `'0x10'` and other even-length hex strings are block numbers (P4-L-11).
- `to: null` means "no receiver" (a contract creation) in `sendTransaction` and `getTransactionFromOrToAttr`, like an absent `to`, instead of being rejected with `Invalid value given "undefined"` (P4-L-12).
- `getBlockNumber`, `getBalance`, `getTransactionCount`, `estimateGas` and `getBlockTransactionCount` reject a reply that is not a hex quantity, and `getStorageAt`, `getCode`, `sign` and `signTypedData` a reply that is not hex encoded bytes, with an `InvalidResponseError` instead of returning the raw value (P4-L-13).
- The block-timeout watcher skips a `newHeads` header whose `number` is not an unsigned hex quantity (shared `isValidUnsignedHexNumber`, which now also rejects `'0x'`) instead of throwing out of the `data` listener, and such a header no longer cancels the polling fallback (P4-L-14).
- `hashMessage()`/`sign()` classify a message like `sha3`: only a `0x`/`0X`-prefixed strict hex string is hashed as bytes, `-0x…` and every other string as UTF-8 text, and an odd-length hex string throws `InvalidBytesError` instead of a validator error quoting the message (P4-L-43).
- `decrypt()` checks the whole keystore address label: the `Q` prefix must be present (`X…`, `q…` and `0x…` labels are a `KeyStoreMismatchError`) and the hex body is compared case-insensitively; `nonStrict` string parsing restores the `Q` it lower-cased (P4-L-44).
- `Wallet.add()` accepts a 51-byte `Uint8Array` seed and throws a `Web3ValidatorError` for `null`, a number or an object without a string `address` instead of a raw `TypeError` (I-6).
- `TransactionFactory.fromTxData()` documents that `type` is required (type 2 only, no legacy default); `serialize()`, `raw()` and `fromValuesArray()` document that the unsigned encodings are library-internal and not decodable by go-qrl; `getSenderAddress()`/`getSenderPublicKey()` document that `verifySignature()` must hold first (I-2, I-3, I-4).

- `Web3SubscriptionManager`: a provider change drops every subscription locally at once, sends `qrl_unsubscribe` to the previous provider inside a `try/catch` bounded by `UNSUBSCRIBE_ON_PROVIDER_CHANGE_TIMEOUT` (5 s), and reports a refusal, transport failure or timeout through the subscription's `error` event (or the manager's new `error` event) only when listened, never as an unhandled rejection; `removeSubscription()` deletes the entry and clears `sub.id` even when the node refuses `qrl_unsubscribe`. (M-7f)
- `Web3Context.link()` (and therefore `registerPlugin()`) adopts the parent's request manager without calling `setProvider` on it, and `Web3RequestManager.setProvider()` with the provider already in use is a no-op, so live subscriptions survive `registerPlugin()` and the provider `message` listener is attached once, kept by reference, moved on a provider change and never duplicated. (L-36)
- The provider `message`/`data` listener is attached on the first `addSubscription()` and detached when the last subscription is removed; contexts that never subscribe leave nothing on a shared provider. New `Web3SubscriptionManager.dispose()` and `Web3Context.dispose()` release the provider listener, the provider-change listeners on the request manager and the `CONFIG_CHANGE` forwarders registered by `use()`/`link()`. (L-37)
- Batch replies from legacy and EIP-1193 providers are validated like a web3 provider's on every path: a reply that is not an array of result or error replies (`[null]`, a member without `result` and `error`, `[]`, a bare value, a single object) rejects with a `ResponseError` instead of hanging the entry promises or throwing a raw `TypeError`; a thrown batch response array is returned as the batch reply so its error members are reported per entry. (L-38)
- `Web3Config.setConfig()` routes every known option through its setter, so `CONFIG_CHANGE` is emitted per option and child contexts created with `use()`/`link()` follow; an unknown option throws an `InvalidMethodParamsError`. (L-39)
- `web3-net` validates `net_version` and `net_peerCount` replies (non-negative integer as decimal string, hex quantity, number or bigint) and `net_listening` replies (boolean) before formatting and throws an `InvalidResponseError` naming the method for anything else, instead of returning `"abc"`, `null`, `{}` or `"yes"` to the caller. New `createInvalidResponseError(method, expected, result)` helper in `@theqrl/web3-core`. (L-40)
- `new Web3({ provider, wallet, accountProvider })` keeps the supplied wallet (it becomes `web3.wallet` and `web3.qrl.accounts.wallet`) and account provider instead of replacing them with a fresh empty wallet; the TSDoc of `web3.qrl.Contract` no longer claims a static `setProvider`, and the `Web3` TSDoc shows the IPC provider as an `@theqrl/web3-providers-ipc` instance instead of `Web3.providers.IpcProvider` or a path string. (L-41)

(L-42)
- `qrlRpcMethods.getFeeHistory()` throws a `Web3ValidatorError` for a `rewardPercentiles` argument that is not an array (`null`, `undefined`, a string) instead of a raw `TypeError`; `qrlRpcMethods.getProof()` validates every storage key as `bytes32` (the `bytes32[]` schema only checks the array shape); `getLogs()` with non-array `topics` is covered by a regression test (typed since the phase-1 validator fix). (L-26)
- Request manager error mapping: a revert is decoded as a `ContractExecutionError` in `useRpcCallSpecification` mode as well (it used to become an `InvalidInputError`/`RpcError` and lose the revert data), EIP-1474 code `3` is a revert even without "revert" in the message, and EIP-1193 provider errors (4001, 4100, 4200, 4900, 4901) are thrown as `EIP1193ProviderRpcError` keeping their code in both modes. (I-14)
- `Web3BatchRequest.add()` throws an `InvalidMethodParamsError` for an explicit id already used by another entry instead of silently replacing it; `Web3SubscriptionManager.addSubscription()` rejects with a `SubscriptionError` when the node hands out a subscription id that is already in use (the first subscription stays intact); a provider `message` event without a payload is ignored instead of throwing into the provider's `emit`. (I-14)
- `Web3RequestManager.setProvider('')` / `new Web3('')` / `new Web3Context('')` throw an `InvalidProviderError`, and a non-object, non-string provider argument (`new Web3(true)`, `setProvider(5)`) throws a `ProviderError` instead of a raw `TypeError`; the autodetection error message redacts credentials and paths of the URL. (I-14)
- `contract.methods['f(int256)'](...)` and `contract.methods['0x…'](...)` now encode exactly the overload they name; the name key resolves overloads by arity, then validation, then exact JavaScript-type matches and throws a `Web3ContractError` instead of guessing when the arguments still fit more than one overload (`f(uint256)` vs `f(int256)` given `7`). The signature-key type (`ContractBoundMethodBySignature`) accepts arguments from TypeScript. (H-4)
- `new web3.qrl.Contract(abi, address)` and `new Contract(abi, address, {}, context)` attach to the context: an empty object is no longer taken for a context, and a `Web3Context` instance given as the context shares its request manager, subscription manager, wallet and config. (M-6)
- `contract.events.X()` no longer emits `error` without a listener (which terminated the process on a `qrl_subscribe`, `qrl_getLogs` or HTTP-provider failure); the failure is reported on the new `subscription.subscribed` promise and on `error` when listened, and the subscription starts on the next microtask so listeners attached right after the call are in place. - `QRNS.registryAddress` is honoured: the registry contract is repointed lazily to the explicitly set address, else to the address `checkNetwork()` detected for the current provider, else mainnet; the detection cache is forgotten when the provider changes. (L-62)

(L-71)
- Typed errors instead of raw `TypeError`s: a non-array JSON interface (`ContractMissingABIError`), a non-object ABI item (`Web3ContractError`), `null` as the address or options (accepted as absent), a non-object log entry or non-array `topics` in a `qrl_getLogs` reply (`ResponseError`), a zero, invalid or non-string QRNS resolver address (`Web3ContractError`), and `supportsInterface('')` (`Web3ContractError`); a QRNS registry call failure keeps its web3 error class (an ABI decoding failure is no longer reported as "Transaction has been reverted by the QRVM"), a node revert becomes `TransactionRevertInstructionError` and anything else a `Web3ContractError` carrying the cause. (L-26)

(I-13)
- `sendTransaction` and `sendSignedTransaction` decided the success of a transaction on the receipt formatted with the caller's `returnFormat`, with a deny-list on `0n`: a reverted transaction resolved as a success under `FMT_NUMBER.NUMBER`, `HEX` or `STR`, and so did a receipt whose `status` was missing, `null`, boolean or unparseable. A failed poll is retried on the next tick up to `MAX_CONSECUTIVE_POLLING_ERRORS` (5) times in a row before the last error is thrown. (L-49)

The QRL subscriptions now report a failed backfill, and any notification they cannot decode, on the `error` event when a listener is attached and log a warning otherwise, so the failure stays observable without an unhandled rejection. (M-7d)
- `SyncingSubscription` threw raw `TypeError`s out of the provider's message listener for a malformed `syncing` notification and dropped it silently. The notification shape is validated (`boolean`, or `{ syncing: boolean, status: object }`) and anything else is reported as a `SubscriptionError` through the guarded error path. (L-53)
- Confirmation watching counted one confirmation too many and sent one request too many (`[1,2,3,4]` for `transactionConfirmationBlocks = 3`), started a second counter when `newHeads` data arrived after `blockHeaderTimeout` (`[1,2,3,4,2,3,4]`), and dropped a receipt without `blockNumber` silently. (L-54)

Only `ContractExecutionError`s and error replies with the execution error code `3` are revert reasons; any other error rejects the send unchanged. When a receipt proves a revert and the reason lookup fails, the revert is reported without a reason instead of being hidden. (L-52)

(L-26)

### Security

- The HTTP provider refuses redirects by default (`redirect: 'error'`), so the JSON-RPC body and custom authentication headers are never re-sent to another host; callers can opt in through `providerOptions.redirect`.
- Keystore decryption rejects any `crypto.cipher` other than `aes-256-gcm` with `InvalidCipherError`.
- `seedToAccount` validates every seed through `parseAndValidateSeed`: exactly 51 bytes, as a `0x`-prefixed hex string or a byte array, with no whitespace or separators.
- The ABI decoder rejects non-canonical words (non-zero high bits in integers, booleans other than 0 or 1, non-zero padding in fixed-size bytes) instead of decoding them silently, matching the on-chain decoder.
- `sendSignedTransaction` only uses the sender embedded in a raw transaction for the pre-flight simulation when the transaction's signature verifies.
- Raised the `launch-editor` patch floor to 2.14.2 (CVE-2026-112942, command injection) so the Trivy supply-chain gate passes again.
- Pinned the `@theqrl/qrl-contracts` archive's SHA-512 integrity in the lockfile so pnpm rejects altered downloads. `pnpm run doctor` guards the archive pin and checks the installed tree against a reviewed digest.
- Updated vulnerable tooling dependencies and documented the temporary exception for the unfixed `braces` advisory, whose glob patterns are controlled by repository/tool configuration.
- Upgraded `image-size` to the fixed release verified against its Codeberg source and removed its two advisory exceptions.
- The IPC chunk parser finds message boundaries with one linear scan (string and escape aware bracket depth) instead of re-parsing an ever-growing prefix after every unparseable fragment, so a peer can no longer block the event loop for tens of seconds per 15-second window with a few hundred KB of garbage. Garbage and malformed segments are reported once per `data` event.
- A malicious or misbehaving WebSocket endpoint can no longer wedge a client for the lifetime of the process with one accepted TCP connection, nor leak a socket per manual retry. (M-8)
- A node reply can no longer crash the caller with a stack overflow through nested revert `data`, nor inject a `stack` or `name` into the error the caller inspects. (L-45)
- RPC URL credentials and API keys embedded in URL paths no longer reach error messages, logs or telemetry through transport errors or `InvalidClientError`. (L-48)
- `extraParams` must be empty until the field is specified, matching go-qrl ("non-empty extraParams not supported"): `fromTxData`, `fromValuesArray` and raw-transaction decoding reject a non-empty value, `validate()` reports it, `verifySignature()` returns `false` for it and `sign()` throws `TransactionSigningError` instead of silently dropping it. (L-15)
- Six crash paths closed at their source in web3-core: a node error reply to a batch member, a refused or unanswered `qrl_unsubscribe` during a provider switch, and malformed batch replies no longer terminate a Node.js consumer or leave promises pending forever; failures stay observable through typed errors, `execute()`'s reply array and guarded `error` events. (M-7a, M-7f, L-38)
- Untrusted `net_version`/`net_peerCount`/`net_listening` replies can no longer reach consumers as arbitrary strings, objects or booleans. (L-40)
- Overload keys and the name key can no longer encode a different function than the one the caller named; a wrong-checksum contract address is rejected before it becomes `to` of a signed transaction; a method call can no longer be turned into a contract creation; hex-looking QRNS names no longer collide with other names. (H-4, L-57, I-13, M-11)
