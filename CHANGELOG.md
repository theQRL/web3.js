# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- Fixed-size ABI byte inputs (`bytesN`) must contain exactly N bytes; callers must pad deliberately instead of relying on implicit padding. Seed strings require a lowercase `0x` prefix.
- Updated the fixture compiler to `@theqrl/hypc` 0.2.0 and regenerated contract ABIs and bytecode with optimization enabled (200 runs), keeping PublicResolver within go-qrl's deployed code size limit.
- Limited `compile:contracts` to generating and formatting contract fixtures.
- Configured local testnet client and helper images using published tags, including a compatible AMD64 genesis generator.
- `@theqrl/web3-utils` now ships a dependency-free `EventEmitter` with the Node `events` API subset the library uses, and `Web3EventEmitter`, `Eip1193Provider`, `ChunkResponseParser` and `Common` use it instead of the Node core module, so browser bundles no longer need an `events` polyfill. Unlike Node's emitter, emitting `error` without a listener returns `false` instead of throwing, so an unobserved internal error can no longer terminate a consumer through an uncaught exception. (L-66, M-7)
- Removed the unused `hardhat` and `in3` devDependencies of `@theqrl/web3` together with the dummy `hardhat.config.js`, the `adm-zip` override and the `keccak`/`secp256k1` build-script approvals they justified; `undici@<6.27.0` and `ws@7` overrides stay because `@semantic-release/npm` and `isomorphic-ws` still reach them. (L-67)
- Made the npm publish loop of the release workflow idempotent (`scripts/release/publish-tarballs.js`: versions already on the registry are skipped, one failure no longer stops the loop) and create GitHub releases as drafts that are published only after every tarball is on npm; documented the recovery procedure for a failed run in `RELEASE.md`. (L-68)
- Run `multi-semantic-release` with `--deps.prefix=^` so published manifests carry caret ranges for sibling packages instead of exact pins, and documented the range policy. (L-69)
- Made `@theqrl/eslint-config-base-web3` `"private": true`; it is a workspace-only tool and is no longer part of the publishable package list. (L-70)
- Removed declared-but-unused runtime dependencies (`@theqrl/wallet.js` and `@theqrl/web3-providers-ws` from `@theqrl/web3-qrl`, `@ethersproject/bignumber` and `@theqrl/web3-validator` from `@theqrl/web3-qrl-abi`, `@theqrl/web3-validator` and the optional `@theqrl/web3-providers-ipc` from `@theqrl/web3-core`, the `@theqrl/web3-qrl-abi` peer of the plugin example), pruned stale `allowBuilds` entries and dead overrides from `pnpm-workspace.yaml` (`pnpm run doctor` now fails on an `allowBuilds` key absent from the lockfile), deleted the unused root `jest.config.js`, the dead `.lintstagedrc.json` and the ignored `docs/.env`, made `scripts/clean.sh` prune `node_modules`, and moved `webpack-bundle-analyzer` to devDependencies. (I-8)
- CI hardening: the Codecov token is passed only to the upload steps; the release job no longer requests `issues: write`/`pull-requests: write` (issue and PR comments are disabled in `.releaserc.json`); the Trivy container mounts the repository read-only; `pnpm run doctor` fails when a `.trivyignore` revisit date is missing or has passed; the dependency-review action carries a real licence deny list; a `pre-commit` hook runs `pnpm run hygiene`. (I-9)
- Threat model: the cross-implementation vectors question is closed with the Go harness results and the remaining open items are listed. (threat model)
- `@theqrl/abi` exports `booleanToBit`, the mapping from the accepted explicit boolean forms to the encoded bit.
- `InvalidConnectionError` appends `Reason: <code>` to its message when constructed with an event carrying a `reason`. (L-47, L-48)
- `HttpProviderOptions.providerOptions` documents that credentials belong in `headers`, how per-request headers merge, and that `redirect: 'follow'` re-sends the body and every custom header to a same-host redirect target. (L-48, I-15)
- `Web3BaseProviderConstructor`'s `net` parameter and the `Withdrawals` / `withdrawalsRoot` types are marked `@deprecated` (Ethereum leftovers kept for compilation). (I-15)
- New error codes `ERR_CONN_HTTP_STATUS` (508) and `ERR_REQUEST_SERIALIZATION` (608); new export `redactClientUrl` from `web3-errors`.
- `decrypt()` accepts keystores written by `gqrl --lightkdf` (Argon2id `m = 4096`): the memory floor on decrypt is `ARGON2ID_DECRYPT_MEMORY_MIN` (4096 KiB) while `encrypt()` keeps the 19456 KiB floor and never creates a light keystore. `validateArgon2idParams` takes an optional `'encrypt' | 'decrypt'` purpose. (L-72)
- Non-numeric Argon2id parameters in a keystore (for example `"m": "19456"`) are now reported by the schema as `Web3ValidatorError` (without echoing the value) instead of `InvalidKdfError`; out-of-range numbers are still `InvalidKdfError`. (L-17)
- `sha3`, `sha3Raw` and `keccak256` share one rule for string input, now documented in their TSDoc: a string starting with `0x`/`0X` that is valid hex is hashed as bytes (an odd-length or malformed `0x…` string throws); every other string, including `-0x…`, is hashed as UTF-8 text. `sha3('0X…')` therefore hashes bytes (it used to hash text) and `keccak256('-0x…')` hashes text (it used to throw). To hash hex-looking text as text, pass `utf8ToBytes(text)`. (M-11, I-11)
- `MAX_NESTING_DEPTH` is exported from `@theqrl/web3-utils`. (L-31)
- Configuration setters (and `setConfig()`) validate their input and throw an `InvalidMethodParamsError` naming the option: booleans for `handleRevert`; a block tag or block number for `defaultBlock`; a QRL address or `undefined` for `defaultAccount`; positive numbers for `transactionSendTimeout`, `transactionPollingInterval`, `transactionPollingTimeout`, `transactionReceiptPollingInterval`, `transactionConfirmationPollingInterval` and `blockHeaderTimeout`; a positive integer for `transactionBlockTimeout`; non-negative integers for `transactionConfirmationBlocks` and `maxListenersWarningThreshold` (validated before any `CONFIG_CHANGE` is emitted); `'data' | 'input' | 'both'` for `contractDataInputFill`; non-negative integers (number, bigint, decimal or hex string) for `defaultNetworkId`, `defaultTransactionType` and `defaultMaxPriorityFeePerGas`; non-empty strings for `defaultChain` and `defaultHardfork`; an object with a `customChain` for `defaultCommon`; an object of boolean flags for `enableExperimentalFeatures`; functions for `transactionBuilder` and `transactionTypeParser`. `setConfig()` ignores a `__proto__` key. (L-39, I-14)
- `Web3SubscriptionManager` is now a `Web3EventEmitter` with an `error` event; `Web3Subscription` gained `_markUnsubscribed()`; `@theqrl/web3-core` exports `UNSUBSCRIBE_ON_PROVIDER_CHANGE_TIMEOUT`, `Web3SubscriptionManagerEvents`, `Web3ConfigChangeEvent` and `createInvalidResponseError`. (M-7f, L-37, L-40)
- `Web3RequestManager.sendBatch()` resolves with a batch response array that a legacy or EIP-1193 provider threw (its error members are reported per entry, as on the web3-provider path) instead of rejecting with the raw array. (L-38)
- `Contract.getPastEvents`, `contract.events.X()` and `encodeEventABI` document the filter-matching, log-filtering and subscription error semantics above; `LogsSubscription.subscribed` is new; `encodeIndexedTopic` and `isIndexedHashType` are exported from `@theqrl/web3-qrl-contract`.
- `QRNS.registryAddress` is now an accessor that validates the address (`InvalidAddressError`); `Registry.address` is a new accessor; `interfaceIds.multicoinAddr` / `methodsInInterface.multicoinAddr` were added for `addr(bytes32,uint256)`.
- The `@theqrl/web3-qrl-contract` module docs show the provider as a constructor option or an instance `setProvider` call instead of a non-existent static `Contract.setProvider`.
- `sendTransaction`/`sendSignedTransaction` `error` event: with a listener attached, every failure is emitted as a typed error (errors that are not web3 errors are wrapped in a `TransactionError` with the original as `innerError`) and the internal rejection is marked as handled, so the documented event-only form no longer terminates a Node.js consumer with an unhandled rejection; without a listener the PromiEvent must be awaited or `.catch`ed. The event payload type is `SendTransactionErrorEvent`. (M-7b)
- Transaction quantities (`value`, `gas`, `gasLimit`, `maxFeePerGas`, `maxPriorityFeePerGas`, `nonce`, `chainId`, `networkId`, `type`) given as JavaScript numbers must be safe integers: `2 ** 53 + 1`, `1e18`, `1.5`, `NaN` and `Infinity` throw `InvalidNumberError` instead of being rounded before signing. Larger quantities must be a bigint, a decimal string or a hex string. (L-55)
- A legacy `gasPrice` on a transaction given to `sendTransaction`, `signTransaction`, `accounts.signTransaction`, `call`, `estimateGas` or `createAccessList` throws `InvalidPropertiesForTransactionTypeError` instead of being dropped and replaced by node-derived fees; `gas` and `gasLimit` given together must agree (`Web3ValidatorError`), `gasLimit` no longer silently overrides `gas`. (L-50)
- `chain`, `hardfork`, `common.baseChain` and `common.hardfork` are checked against the supported names (`mainnet`, `zond`) before signing; `hardfork: 'london'` throws `Web3ValidatorError` instead of being signed as `zond`. (I-12)
- `defaultTransactionBuilder` takes `networkId` from `common.customChain.networkId`, then from `defaultNetworkId`, and asks the node for `net_version` only when neither names it. (I-12)
- `value: ''` is no longer accepted as zero when signing. (L-26)
- `InvalidPasswordError` reads "Password must be a string or a Uint8Array"; empty passwords stay accepted for go-qrl parity. (I-7)
- `web3-types`: `SyncInput`/`SyncOutput` carry go-qrl's `SyncProgress` fields (`syncedAccounts` … `healingBytecode`) instead of Ethereum's `knownStates`/`pulledStates`; `FilterOption` admits byte arrays, object-form tuples, OR-lists of tuples and nested arrays as indexed filter values. (L-71, L-73)
- Contract method sends pass the contract's error ABI to the send pipeline (`contractAbi`), which decodes custom errors before reporting a failure; the contract wrapper no longer attaches an internal `error` listener, so a send that is neither awaited nor listened to keeps the ordinary unhandled-rejection semantics instead of having its failure silently marked as handled. (M-7b)

### Fixed

- Socket providers (WebSocket, IPC) no longer crash the process on a `[null]` reply, no longer treat unparseable or non-object messages as a lost connection, reset their chunk parser on every (re)connection, and accept `0`/`""` as JSON-RPC ids. WebSocket frames are parsed independently, so one malformed frame can no longer poison every response that follows it.
- IPC incomplete-message timeouts expire 15 seconds after the first chunk even under continuous traffic. Parser errors reject affected requests without detaching the live socket's listeners, allowing later replies to succeed.
- `ResponseError`, `InvalidResponseError` and the JSON-RPC shape predicates tolerate `null` entries in batch responses instead of throwing a `TypeError`.
- Setting `defaultCommon` on a context no longer makes local signing fail with `CommonOrChainAndHardforkError`, an explicit `chain`/`hardfork` pair takes precedence over it, the transaction `chainId` is taken from the adopted `common` instead of being left unset, and the context's `defaultCommon` object is no longer mutated during signing.
- Removed unused runtime dependencies (`@theqrl/wallet.js` and `crc-32` from web3-qrl-abi, `util` from web3-validator, `@ethersproject/strings` from abi).
- Replaced stale Ethereum-era examples (secp256k1 keys, 65-byte signatures, legacy raw transactions, 20-byte addresses) in the accounts and Web3QRL documentation and in the secrets template.
- Made the ESLint regression test use an on-disk fixture and exercise both CI and local parser modes.
- Resolved Jest types in ESLint's strict TypeScript project so valid test assertions no longer inflate warning counts, and lowered the warning budgets to match.
- Contract compilation now exits unsuccessfully on compiler errors, missing contract artifacts, and filesystem errors. Compilation failures preserve the existing fixtures; warnings do not prevent successful builds.
- WebSocket integration tests now connect to the local testnet's WebSocket port (8546).
- Updated the local testnet to the upstream QRL package with compatible Qrysm startup flags and epoch settings for its compiled state limits.
- Updated revert and access-list gas expectations for the regenerated contract fixtures.
- `encodeParameter`/`encodeParameters` accept negative decimal strings for signed integer types narrower than 256 bits (for example `'-57'` for `int8`); decimal strings are no longer zero-padded before encoding, only hex strings are width-normalised.
- `waitForTransactionReceipt` (and therefore `sendTransaction`/`sendSignedTransaction`) stops polling `qrl_getTransactionReceipt` once the polling or block timeout has rejected, including when the initial block-number request fails or stalls. Late block-watcher setup is cleaned up, and cancelled subscription watchers cannot restart polling through their fallback timer or late error events.
- `trySendTransaction` handles failed or stalled block-watcher setup within the send timeout and cleans up its timer, preventing a later unhandled `TransactionSendTimeoutError` from terminating Node. Setup that finishes after the timeout is cleaned up without sending the transaction.
- Replies whose `error` member is `null`, or whose revert `data` / `data.originalError` is `null`, surface as `ResponseError` / `ContractExecutionError` instead of a raw `TypeError`. `isResponseWithError` requires `error` to be an object, as JSON-RPC 2.0 defines it, and the request manager no longer returns such a malformed envelope from a legacy or EIP-1193 provider as if it were a result.
- Event logs delivered without `topics` no longer throw a `TypeError` on the `allEvents` path; a declared anonymous event with more indexed inputs than topics reports an `AbiError`; a subscription that cannot decode a notification reports it on its own `error` event instead of only the provider's.
- Keystore decryption reports a wrong password or tampered ciphertext as `KeyStoreDecryptionError` (new, code 715), a wrong-length IV as `IVLengthError`, and a non-bytes salt as a validation error, instead of leaking a WebCrypto `DOMException` or a library `TypeError`. Encryption and decryption report out-of-range Argon2id parameters and salts shorter than 8 bytes as `InvalidKdfError`, preserving the validation reason; accepted salt byte arrays are normalized before key derivation.
- Declared `@theqrl/qrl-cryptography` as a runtime dependency of `@theqrl/abi`; under a strict resolver (pnpm isolated linker, Yarn PnP) `require('@theqrl/abi')` and every package depending on it threw `MODULE_NOT_FOUND`. Added `scripts/check-package-dependencies.js` (`pnpm run check:dependencies`, part of `pnpm run doctor` and `pnpm run release:inspect-packages`), which parses each package's `src` and built `lib` with the TypeScript compiler and fails on an import that is not a declared dependency, or on a Node built-in loaded by the built output of a browser-facing package. (L-65, L-66)
- Documented the providers correctly: an IPC socket path is never auto-detected and there is no `Web3.providers.IpcProvider`; the guide now constructs `new IpcProvider(path)` from `@theqrl/web3-providers-ipc`, and the static `web3.Contract.setProvider` / `web3.qrl.Contract.handleRevert` examples were replaced by the context option (`web3.handleRevert = true`) and instance calls. (L-41)
- Corrected documentation drift: the QRL basics guide signs with a 51-byte extended `seed` instead of a `privateKey`; the contract tutorial calls the real compiler CLI (`npx hypcjs`, shipped by `@theqrl/hypc`) instead of the non-existent `@theqrl/hypcjs`; the type-inference guide no longer embeds an Infura Goerli URL; the `@theqrl/web3-rpc-methods` README badges point at the right package; `RELEASE.md` no longer claims a changelog write-back, names Node 22.15.0 and documents post-release verification in place of a missing link; `docs/audit-evidence.md` drops the non-existent `test:e2e:gqrl:ipc` script and the stale runner note; the README scripts table lists the real root scripts; the black-box test manifests track the current package version and state that they are manual-only. (I-7)
- Fixed the comment in `scripts/release/pack-packages.js` that attributed the `workspace:` substitution to `pnpm pack` alone. (L-69)
- `BooleanCoder.encode` (`@theqrl/abi`) and `formatParam` (`@theqrl/web3-qrl-abi`) now encode a `bool` by value from exactly the forms the validator accepts (`true`/`false`, `0`/`1`, `0n`/`1n`, `'0'`/`'1'`, `'0x0'`/`'0x1'`) and reject anything else (`'false'`, `2`, `{}`, ...) with an error instead of encoding JS truthiness, so `setFlag('0')` and `encodeParameter('bool', '0')` encode `false` on the contract, parameter, function-call and typed-data paths. (H-3)
- `Reader.subReader` shares the parent's buffer instead of copying the rest of it, and every read is accounted against one budget of 16 times the input length (`MAX_INFLATION`), so a reply whose dynamic-array elements all point at the same bytes decodes in linear time and a reply whose elements share one large payload is rejected with `compressed ABI data exceeds inflation ratio` instead of taking minutes. `BytesCoder.decode` builds its hex string from ASCII digit bytes in one step instead of ethers' per-character concatenation, whose rope of one heap object per byte made large `bytes` results (and the rejection of an inflated reply) spend seconds in the garbage collector or exhaust the heap. (M-9)
- `ArrayCoder.decode` applies the "enough data" bound to fixed-length arrays before allocating anything and shares one anonymous coder between the elements; `ParamType` rejects a fixed array length that is not a safe integer below 2^32 with `array length out-of-bounds`, so an ABI such as `uint8[100000000]` on one word of data fails with `insufficient data length` instead of a fatal V8 OOM. A zero-length static array type (`T[0]`) is rejected, and the decoder also counts array elements against a shared budget (16 times the number of input words), because nested arrays of zero-size elements (`tuple()[][]`) satisfy the data-length check at every level while reading nothing: 125 KiB of such data used to decode a million result objects. (M-10)
- `decodeContractErrorData` requires a hex string carrying a full 4-byte selector, matches the selector exactly and case-insensitively, sets `errorName`/`errorSignature`/`errorArgs` only after the arguments decoded, and no longer prints node-controlled data with `console.error`: a bare `revert()` (`data: '0x'`) is left undecoded instead of being attributed to the first error of the ABI. (L-33)
- `decodeLog` rejects a non-array `inputs`, non-hex `data`, empty `data` for an event with non-indexed inputs and a log with more topics than the event has indexed inputs with an `AbiError`; a parameter named `__length__` or like an `Object.prototype` member (`__proto__`, `constructor`, `toString`, ...) is exposed by position only, so an ABI can no longer re-parent the result or corrupt its counter. `decodeParameters` likewise keeps a `__length__`-named output out of the counter. (L-34)
- The human-readable type parser rejects whitespace inside array brackets (`uint256[ 2]`) with `unexpected character` instead of parsing a dynamic array named `2`. (L-35)
- `getEncodedQRLTypedData` validates the payload (`types`, `types.QRLTypedDataDomain`, `primaryType`, `domain`, `message`, field definitions) and the values (`string` must be a string, `bytes` an even-length hex string or `Uint8Array`, struct values objects, field data an own property) and throws `AbiError` for malformed input and for coder failures instead of hashing garbage or a raw `TypeError`. `FunctionCoder.decode` rejects a selector word with non-zero padding; `ParamType.fromObject`/`Fragment.fromObject` reject a null or non-object fragment, a non-string `type` and non-array `inputs`/`outputs`/`components` with an argument error instead of a `TypeError`; `jsonInterfaceMethodToString`/`mapTypes` reject a parameter without a type with `AbiError`; `Parameter encoding error` messages now carry the coder's reason. (I-10)
- `WebSocketProvider.getStatus()` reports `'disconnected'` as soon as the connection deadline (or `disconnect()`) marks the provider so, even while the underlying socket is still `CONNECTING`; the provider's `connectionTimeout` is passed to `ws` as `handshakeTimeout` (a caller's `socketOptions.handshakeTimeout` still wins), so a peer that accepts TCP but never completes the upgrade is abandoned, the socket closed and the reconnect cycle started instead of wedging the provider for the process lifetime. (M-8)
- `WebSocketProvider` closes a still-connecting or open previous socket before opening a new one in `connect()`, so a timed-out handshake or a reconnect race no longer leaks an orphaned connection that `disconnect()` cannot close. (M-8, L-44)
- `IpcProvider` decodes the socket's byte stream with `setEncoding('utf8')` (and a streaming `TextDecoder` for binary chunks, reset per connection), so a multi-byte UTF-8 character split across two `data` events is reassembled instead of becoming two U+FFFD; the socket `error` listener is added only when absent, so `reset()` no longer accumulates one listener per call. (L-24)
- `IpcProvider` treats the `net` `'close'` event like a lost connection: with `autoReconnect` it marks the provider disconnected and schedules a (bounded) reconnect, otherwise it clears the queues and emits `disconnect`. A connection attempt that fails with `ECONNREFUSED` (a stale `.ipc` file left by a crashed node) now counts against `maxAttempts`, ends in `MaxAttemptsReachedOnReconnectingError`, and the next `request()` reconnects; the provider used to stay `'connecting'` forever with every request failing only at `requestTimeout`. The socket path is checked with `statSync().isSocket()` so a regular file, directory or FIFO is refused at construction with a typed `ConnectionError`. (L-43)
- `Eip838ExecutionError` unwraps at most the one documented level of provider `data` (`data.data` / `data.originalError.data`), accepts `data` only when it is a string and never copies a provider-supplied `name` or `stack`; a reply with `data` nested thousands of levels deep used to overflow the stack (a bare `RangeError` instead of `ContractExecutionError`) and a provider could inject a trace. (L-45)
- `TransactionOutOfGasError`, `ChainIdMismatchError`, `ChainMismatchError`, `HardforkMismatchError`, `TransactionMissingReceiptOrBlockHashError` and `TransactionReceiptMissingBlockNumberError` render their values with `BaseWeb3Error.convertToString`, so a receipt or chain id in BigInt format no longer turns the typed error into `TypeError: Do not know how to serialize a BigInt`. (L-46)
- `HttpProvider` rejects a non-2xx reply with the new `HttpStatusError` (`status`, `statusText`, `retryAfter` in seconds, `retryable`, the body as a `ResponseError` `innerError` when it was a JSON-RPC error reply, and that reply's `error.data` as `data` so a revert reported with a non-2xx status stays decodable) instead of a `ResponseError` whose message was a JSON parse failure; a refused redirect is a `ConnectionError`; a refused connection, DNS failure or undici `fetch failed` is an `InvalidConnectionError` carrying the endpoint's `host:port` and the transport's error code. (L-47)
- Error messages no longer carry RPC URL credentials or paths: transport errors are wrapped as above instead of re-thrown with node-fetch's `request to <full url> failed` text, and `InvalidClientError` / `InvalidProviderError` redact the user-info and the path of the URL they echo (`http://***@host:port/[redacted]`). (L-48)
- `HttpProvider` and `WebSocketProvider` derive the host of the cleartext warning from `new URL(url).hostname`, so a URL with credentials no longer prints the username as the host, loopback URLs with credentials no longer warn, and IPv6 literals are recognised. (I-15)
- `HttpProvider` validates the URL with the WHATWG parser at construction, so `http://127.0.0.1:99999/` and `http://` throw `InvalidClientError` instead of a raw `TypeError: Invalid URL` on the first request. (I-15)
- All three providers reject a payload that cannot be serialised (a `bigint` in `params`, a circular structure, a throwing `toJSON`) with the new typed `RequestSerializationError` before anything is sent, instead of a raw `TypeError` from `JSON.stringify`. (I-15)
- `BaseWeb3Error` captures its stack trace onto the instance (`Error.captureStackTrace(this, new.target)`); it used to define a `stack` property on the global `Function` object at every construction. (I-15)
- `ConfigChainMismatchError.code` is `ERR_CORE_CHAIN_MISMATCH` (1102) instead of the hardfork code. (I-15)
- `RpcError` no longer throws a `TypeError` when the node reply lacks `error.code`. (I-15)
- `InvalidValueError` truncates the echoed value to 256 characters and `BaseWeb3Error.convertToString` never throws (a circular value or a throwing `toJSON` renders as `[unserialisable object]`), so a multi-megabyte or circular input no longer produces a multi-megabyte message or a raw `TypeError`. (I-15)
- `InvalidResponseError` names an id mismatch (`Invalid JSON-RPC response: response id 999 does not match request id 1`) instead of the empty `Returned error: `. (I-15)
- `HttpProvider` merges per-request `headers` on top of the constructor's `providerOptions.headers` as documented (case-insensitive by header name, the per-request value winning) and adds `Content-Type: application/json` unless a `content-type` header was supplied explicitly; per-request headers used to replace the constructor's and two spellings of one header could both be sent. (I-15)
- `web3-types`: `qrl_clearSubscriptions` (a client-side helper, not an RPC method) is removed from `QRLExecutionAPI`; `qrl_createAccessList` and `qrl_maxPriorityFeePerGas` are added; `Filter.blockHash` is a 32-byte hash (`HexString32Bytes`) instead of an `Address`; `ConnectionEvent` fields are optional, matching what the IPC provider reports. (I-15)
- `signTransaction()` and `sign()` validate the seed through `parseAndValidateSeed`, so a malformed seed (trailing newline, whitespace, separators, missing or `0X` prefix, wrong length) is rejected with a value-free `InvalidSeedError`/`SeedLengthError` instead of a validator error that echoed the seed; `decrypt()` rejects a password that is neither a string nor a `Uint8Array` with `InvalidPasswordError` before any validation. (M-12, L-11)
- `hashMessage()` hashes the raw UTF-8 bytes of the message, so leading and trailing NUL characters are no longer stripped and the result equals go-qrl's `accounts.TextHash` for every input; keystore passwords are encoded the same way (`[]byte(auth)`). (L-14)
- Keystore `dklen` must be exactly 32 (the AES-256-GCM key length); `encrypt` and `decrypt` report any other value as `InvalidKdfError` before the key derivation runs, instead of an untyped AES error or a misleading "wrong password". (L-12)
- `FeeMarketEIP1559Transaction.fromValuesArray`/`fromSerializedTx` require every scalar field to be an RLP byte string and the access list to be a list of `[address, [storageKeys]]` byte strings, so a transaction re-encoded with RLP lists (previously flattened back into the original bytes, giving one signed transaction many hashes) is rejected like go-qrl does; `maxPriorityFeePerGas`, `descriptor`, `extraParams`, `signature` and `publicKey` given as arrays are rejected by `fromTxData`; `toUint8Array` refuses arrays with non-byte elements. (L-13)
- `Common` no longer shares mutable chain state: `custom()`, `setChain(object)`, `copy()` and the standard-chain lookup hand every instance a private deep copy of the chain parameters, so `setForkHashes` on one instance (or mutating a configuration object after construction) no longer changes other instances or the module-level mainnet definition; `copy()` also owns its QIP list and starts without listeners. (L-16)
- The keystore schema declares `cipherparams.iv` and the `kdfparams` members `m`, `t`, `p`, `dklen`, `salt` as required with their types and drops the stray top-level `salt`; `decrypt` reports a malformed `iv` as `IVLengthError`, a malformed or wrong-length `ciphertext` as `KeyStoreDecryptionError`, a non-hex salt as `InvalidKdfError` and a keystore string that is not JSON as `Web3ValidatorError`, all before the key derivation. `Wallet.load()` and `Wallet.decrypt()` reject a stored value that is not valid JSON or not an array of keystores with `Web3ValidatorError` instead of a raw `SyntaxError`/`TypeError`. (L-17)
- `signTransaction()` no longer repeats the `Signer Error` prefix for every validation failure; the accounts TSDoc uses 51-byte seeds that actually run, no longer lists the non-enumerable `seed` in `console.log` output, names `seedToAccount` instead of `publicKeyToAccount` in the wallet examples, and the transaction docs no longer mention `signatureYParity/R/S`, EIP-155 or `privateKey`. ### Security

- The HTTP provider refuses redirects by default (`redirect: 'error'`), so the JSON-RPC body and custom authentication headers are never re-sent to another host; callers can opt in through `providerOptions.redirect`.
- Keystore decryption rejects any `crypto.cipher` other than `aes-256-gcm` with `InvalidCipherError`.
- `seedToAccount` validates every seed through `parseAndValidateSeed`: exactly 51 bytes, as a `0x`-prefixed hex string or a byte array, with no whitespace or separators.
- The ABI decoder rejects non-canonical words (non-zero high bits in integers, booleans other than 0 or 1, non-zero padding in fixed-size bytes) instead of decoding them silently, matching the on-chain decoder.
- `sendSignedTransaction` only uses the sender embedded in a raw transaction for the pre-flight simulation when the transaction's signature verifies.
- Raised the `launch-editor` patch floor to 2.14.2 (CVE-2026-112942, command injection) so the Trivy supply-chain gate passes again.
- Pinned the `@theqrl/qrl-contracts` archive's SHA-512 integrity in the lockfile so pnpm rejects altered downloads. `pnpm run doctor` guards the archive pin and checks the installed tree against a reviewed digest.
- Updated vulnerable tooling dependencies and documented the temporary exception for the unfixed `braces` advisory, whose glob patterns are controlled by repository/tool configuration.
- Upgraded `image-size` to the fixed release verified against its Codeberg source and removed its two advisory exceptions.
- The IPC chunk parser finds message boundaries with one linear scan (string and escape aware bracket depth) instead of re-parsing an ever-growing prefix after every unparseable fragment, so a peer can no longer block the event loop for tens of seconds per 15-second window with a few hundred KB of garbage. Garbage and malformed segments are reported once per `data` event.
- A malicious or misbehaving WebSocket endpoint can no longer wedge a client for the lifetime of the process with one accepted TCP connection, nor leak a socket per manual retry. (M-8)
- A node reply can no longer crash the caller with a stack overflow through nested revert `data`, nor inject a `stack` or `name` into the error the caller inspects. (L-45)
- RPC URL credentials and API keys embedded in URL paths no longer reach error messages, logs or telemetry through transport errors or `InvalidClientError`. (L-48)
- `extraParams` must be empty until the field is specified, matching go-qrl ("non-empty extraParams not supported"): `fromTxData`, `fromValuesArray` and raw-transaction decoding reject a non-empty value, `validate()` reports it, `verifySignature()` returns `false` for it and `sign()` throws `TransactionSigningError` instead of silently dropping it. (L-15)
- Six crash paths closed at their source in web3-core: a node error reply to a batch member, a refused or unanswered `qrl_unsubscribe` during a provider switch, and malformed batch replies no longer terminate a Node.js consumer or leave promises pending forever; failures stay observable through typed errors, `execute()`'s reply array and guarded `error` events. (M-7a, M-7f, L-38)
- Untrusted `net_version`/`net_peerCount`/`net_listening` replies can no longer reach consumers as arbitrary strings, objects or booleans. (L-40)
- Overload keys and the name key can no longer encode a different function than the one the caller named; a wrong-checksum contract address is rejected before it becomes `to` of a signed transaction; a method call can no longer be turned into a contract creation; hex-looking QRNS names no longer collide with other names. (H-4, L-57, I-13, M-11)
